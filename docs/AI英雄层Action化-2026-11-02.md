# AI 英雄层 Action 化实现（第一阶段）

实现时间：2026-11-02

## 一、已完成

### 1. 删除 State 枚举

- 删除 `HeroAI.State`；
- 删除 `var state`；
- 新增 `AIAction` + `current_action`。

### 2. 新 Action 数据

文件：`ai/AIAction.gd`

包含：

- `ActionType`
- `ActionStatus`
- `PauseClass`
- priority / target / lane / expiry / reason

### 3. 安全动作栈

- 被塔攻击 → `TOWER_ESCAPE`
- 弹道躲避 → `DODGE`
- 两者可以压栈；
- 安全动作结束后恢复原 Action；
- 其它打断不恢复。

### 4. 团队任务暂停规则

- 生存 Action：可暂停团队任务；
- 环境 Action：一条团队任务最多暂停一次；
- 新团队任务重置环境暂停计数；
- 暂停期间延长 `team_task.expires_at`。

### 5. 环境任务接入

已标记为环境 Action：

- 血包
- 临时清兵
- 视野之灵
- 大禹鼎

临时清兵仍保留整条 A* 路线避塔检查。

### 6. 目标安全

新增：

- `_is_target_safe()`
- `_estimate_tower_hits()`
- `_estimate_burst_damage()`

越塔估算：

- 计算目标生命 + 护盾；
- 加入关键技能可用伤害；
- 估算塔伤次数；
- >2 次则判定不安全。

### 7. 闪现

- 赶路不再使用闪现；
- 闪现只在：
  - `FINISH_CHASE` 且目标残血；
  - 血量 <20% 且高威胁。

### 8. 外部模块适配

- `SummonerTactics`
- `ItemActiveTactics`
- `LanlingBrain`
- `HeroBrain.process_special_actions`

均改为接收 ActionType。

## 二、尚未完成

这一阶段是 Action 化的第一版，仍保留部分旧结构：

1. **完整 ActionScheduler 未完成**
   - 当前仍由 `_decide()` 的硬编码顺序选动作；
   - `current_action` 已存在，但还没有“候选 Action 统一排序”；
   - Action 的 complete/failed 生命周期还未全面接管。

2. **统一路径规划未完成**
   - 普通移动仍走 Hero `_avoid_walls()` 的 A*；
   - 传送阵/传送召唤师技能还没有进入路径代价比较；
   - 闪现没有进入路径边。

3. **Hero 自动追击未关闭**
   - 还没有增加 `ai_path_controlled`；
   - 当前 manual_target 仍会触发 Hero 自动追击。

4. **环境任务动作还不完整**
   - 血包只用了原 lane 血包查找；
   - 敌方血包/安全条件尚未完整实现；
   - 大禹鼎/视野之灵只做了环境暂停接入。

5. **Action 完成条件**
   - 目前 Action 主要作为当前行为记录；
   - 还没有每个 Action 的 `is_complete/is_failed` 统一执行。

## 二点五、第二阶段补充

- `_set_action()` 增加 priority 保护：低优先级不能覆盖当前高优先级 Action；
- 增加 `_action_is_complete()`：
  - TRADE 目标失效；
  - FINISH_CHASE 目标失效；
  - TEMP_CLEAR 清完；
  - TEAM_TASK 任务失效；
  - SAFE_RECALL 已回满；
  - HEALTH_PACK 血量恢复；
  - TRIPOD 目标失效；
  - VISION_SPIRIT 到达。
- 动作完成后置为 COMPLETED，并清空当前 Action；
- 安全动作仍通过栈恢复。

## 二点六、第三阶段补充

- 关闭 Hero 对 AI 的自动追击：新增 `Hero.ai_path_controlled`；
- AI 通过 `_sync_ai_movement()` 统一写 `move_target`：
  - 目标在普攻距离外 → 写目标点；
  - 进入普攻距离 → 清空 move_target；
- 安全血包：
  - 60% 血量以下寻找；
  - 优先安全敌方血包；
  - 敌方血包 20m 无敌人；
  - 若在敌方塔下，我方小兵总血量需 >1500。

## 二点七、第四阶段补充

- 传送增加时间收益判断：只有 `传送引导 4s + 2s` 小于直接走路时间才使用；
- DEFEND_TOWER 完成条件：本线塔不再被攻击；
- RETURN_TO_BASE 完成条件：已回到己方塔下且附近无敌人。

## 二点八、第五阶段补充

- 传送阵接近阶段加入 `ROTATE` Action：
  - 20m 内找传送阵；
  - 用 A* 路径长度估算走到阵的时间；
  - 与直接走路时间比较；
  - 只有明显更快才走向传送阵。

## 二点九、第六阶段补充：候选 ActionScheduler

- `_decide()` 改为候选 Action 统一调度：
  - `_build_action_candidates()` 生成候选；
  - `_pick_candidate()` 按 priority 选最高；
  - 当前高优先级 Action 未完成时，低优先级候选直接跳过；
  - `_execute_candidate()` 再执行具体行为。
- 候选包括：守塔、回城、撤退、换血、临时清兵、大禹鼎、团队任务、本地推线/刷野。
- 团队任务 PUSH 仍交给 LaneStrategy；其它任务执行后不再落本地默认。
- AIAction 增加 `data` 字段，供换血退出等行为携带数据。

## 二点十、第七阶段补充：路径风险与距离

- 新增 `MovementPlanner`：
  - 先取 PathFinder A*；
  - 再生成中点左右 8m/12m 的绕行候选；
  - 代价 = 路径长度/移速 + 风险权重 × 归一化风险；
  - 风险来自 ThreatModel 的敌方英雄记忆和敌塔危险区；
  - 选综合代价最低的路径。
- AI 追击移动改用 MovementPlanner 航点，不再直接直线走向目标。

## 二点十一、第八阶段补充

- 临时清兵无目标时清空 `_temp_clearing`，避免临时清兵 Action 卡死；
- 血包 Action 在血包失效时完成；
- 撤退安全路线也改用 MovementPlanner，按风险+距离选路。

## 二点十二、AI 胶囊

胶囊按最新架构改为两行：

- 第一行：`路:中 · 行:换血p945 · 任:守塔(暂停)`
  - 当前 Action；
  - Action priority；
  - 团队任务及暂停状态。
- 第二行：`胁:敌0.8/我0.5(高) · 标:凯 · 径:R0.32 L42 · 血:对拼`
  - 威胁；
  - 目标；
  - MovementPlanner 路径风险/长度；
  - 换血状态。
- 塔下逃生/躲技能时胶囊颜色变红/橙；
- debug_snapshot 增加 action_type/action_priority/action_pause/team_paused/env_pause_used/path 字段。

## 二点十三、回城回满修复

- `HEALTH_RECOVERED` 从 0.98 改为 1.0；
- `_fully_recovered()` 改为血量/法力必须达到最大值（0.5 浮点容差）；
- 泉水出生点检测增加 `_fully_recovered()` 条件，避免 AI 走进泉水后被出生检测直接派出去；
- 回城 Action 只有在真正回满后才完成；
- 回满后无论是否还在泉水判定圈内，都结束回城并回线，避免走到安全点二次回城；
- 未回满才允许 `start_recall()`，防止已满血仍重新读条。

## 二点十四、撤退规则调整

- 移除“低血 + 敌人靠近”的通用撤退触发；
- `RETURN_TO_BASE` 只由 `TradePlanner` 退出触发；
- 撤退目标只使用 `TradePlanner.safe_pos`，不再回退到最近己方塔；
- 撤退移动只走 MovementPlanner 到该安全点，不再用逃跑位移；
- 优先级从 950 调整为 900；
- 完成条件改为 `_is_threat_low()`：敌方威胁 <0.35 且敌我威胁差 > -1.0。

## 二点十五、临时清兵不攻击修复

原因：临时清兵 Action 存在时，视野之灵/血包等环境逻辑仍可能改写 `hero.move_target`，导致英雄保持“临时清兵”标签却被带离目标；目标死亡/失效时 `_temp_clearing` 也可能残留。

修复：

- TEMP_CLEAR 完成条件增加目标失效/死亡判定；
- 临时清兵期间跳过血包；
- 视野之灵只在 PUSH_LANE/JUNGLE_FARM/TEAM_TASK 时允许，不抢清兵/换血/追击/守塔的移动目标；
- 每帧清理失效的 `_temp_clearing`。

## 二点十六、泉水最高常态约束

长局复现发现：AI 在泉水里血量 97% 时，守塔/团队任务候选可能把它拉出泉，导致“没回满就走两步”。

修复：`_process()` 在死亡检查后增加最高常态约束：

```gdscript
if hero.is_in_own_fountain() and not _fully_recovered():
    _set_action(SAFE_RECALL, 960, SURVIVAL, "泉水养伤")
    _recall_safe_behavior(delta)
    return
```

效果：

- 只要在己方泉水且未回满，任何任务/守塔/换血都不能把 AI 拉出泉；
- 真正回满后才允许重新决策；
- 长局 8000 帧验证：所有 `LEAVE` 均为 `full=true`。

## 二点十七、残血追击呆住修复

原因：开启 `ai_path_controlled` 后 Hero 不再自动追击；`_update_finish_chase()` 每帧设置 `manual_target` 后又把 `move_target` 清零，导致追击目标始终没有移动指令。

修复：残血追击设置 Action 后立即调用 `_sync_ai_movement()` 写移动目标；目标进入普攻距离时由该函数清空 move_target 并攻击。

## 二点十八、推线任务回退己方塔修复

原因链：

1. `TeamTask.PUSH_LANE/PUSH_TOWER` 在 HeroAI 中仍交给 `LaneStrategy.decide()`；
2. `LaneStrategy._is_defensive()` 按附近双方英雄总血量判断，劣势时返回 true；
3. 返回 `_get_defensive_position()`，即**己方该线最外侧塔**；
4. 没有可追击目标时，默认回退 `default_bush_pos`，也位于己方最外侧塔附近。

所以玩家看到“推线任务中的 AI 返回己方最前线防御塔”。

修复：

- `LaneStrategy.decide(force_push)` 增加 force_push；
- 团队 PUSH_LANE/PUSH_TOWER 时传入 true；
- 推线任务下跳过 `_is_defensive()` 回塔分支；
- 没有己方前排兵时原地等待下一波，不退回己方最前线塔。

## 二点十九、泉水缓冲圈防挤出

长局日志发现回城落点有时 `is_in_own_fountain()==false`（单位在落点互相推挤/刚好在判定圈外），旧逻辑就不会进入养伤保持，直接回线。

修复：

- 使用 8m 缓冲圈（泉水判定圈 3.6m）；
- 回城落点附近且未回满时：
  - 取消读条；
  - 3m 外主动走回泉心；
  - 3m 内原地待命；
  - 只有真正回满才允许重新决策；
- 长局 8000 帧验证所有离泉 `full=true`。

## 二点二十、龙坑附近显示推线且原地不动

原因：

1. 打龙集合分支只把 Action 标成 `PUSH_LANE`，胶囊显示“推线”；
2. `_dragon_rally_behavior()` 设置 `manual_target` 后没有当帧调用 `_sync_ai_movement()`，Hero 自动追击又已关闭，于是第一帧没有移动指令；
3. 推线任务无前排兵时 force_push 回退到“原地等下一波”，若 AI 不在本路（例如龙坑）就会一直停在原地。

修复：

- 新增 `AIAction.Type.OBJECTIVE`，打龙集合显示“打龙/资源”；
- 打龙分支设置目标后立即 `_sync_ai_movement()`；
- force_push 无前排兵时，若距本路默认点 >12m 先回本路，否则原地等兵。

## 二点二十一、撤退原地不动修复

原因：`_execute_candidate()` 从 TradePlanner 退出 Action 里读出 `safe_pos`，但调用 `_set_action()` 创建新 Action 时没有把 `a.data` 带过去；`_retreat_behavior()` 再读 `current_action.data["pos"]` 为空，于是把 `move_target` 设为 ZERO，AI 原地不动。

修复：`_set_action()` 增加可选 `data` 参数；撤退执行时传入原 Action 的 `a.data`，安全点随之保留。

## 二点二十二、4分钟后1-3-1按最近敌兵选路

- `TeamTactics._allocate_team(ONE_THREE_ONE)` 改为每个 AI 遍历三路敌方小兵；
- 选出“离自己最近”的敌方小兵所在分路；
- 该路有兵则优先去该路；
- 三路都没有敌方小兵时，才回退原来的主路/相邻路角色分配。

## 二点二十三、撤退数据二次修复

复查发现 `_set_action()` 创建新 Action 时，data 复制代码缺失，只有「同类型 Action」分支复制 data；首次创建 RETURN_TO_BASE 仍然丢失 `safe_pos`。

补回：

```gdscript
current_action = AIAction.new(...)
if not data.is_empty():
    current_action.data = data.duplicate()
```

长局日志确认撤退 Action 的 data 已包含 `"action":"exit","pos":...`，`_retreat_behavior()` 能读到安全点。

## 二点二十四、推线目标二选一

推线默认目标不再固定跟随己方前排兵，而是在两个点中选距离自己更近的：

1. `_get_forward_minion_pos()`：己方最前兵线；
2. `_get_enemy_tower_outside_pos()`：敌方最前线塔外、塔射程+2m 的安全站位。

适用范围：

- 4 分钟后正常推线；
- 团队 PUSH_LANE/PUSH_TOWER 的 force_push；
- 0–4 分钟仍只跟己方兵线，避免开局单人去敌方塔外。

## 二点二十五、打完龙后推线原地不动

原因：

- 打龙集合执行时 Action 为 `OBJECTIVE`，优先级 80；
- 龙死后 `_assign_lane()` 用默认优先级 0 的 PUSH_LANE/JUNGLE_FARM 想切回分路，但被当前 OBJECTIVE 80 的优先级保护挡住；
- OBJECTIVE 没有完成条件，Action 永远不释放；
- 后续团队任务改成推线，但低优先级推线无法覆盖 OBJECTIVE，AI 停在龙坑。

修复：

- `OBJECTIVE` 完成条件：`not is_dragon_rally or not _is_dragon_alive()`；
- `_assign_lane()` 先 `_finish_current_action()` 清空当前 Action，再设置默认分路。

## 二点二十六、回城点算法升级

- `_recall_point_threatened()` 改为“可见敌人 + ThreatModel 最后记忆（时间衰减）+ 敌方小兵”；
- `_recall_path_threatened()` 改为真实 A* 路径逐航点检查，不再用英雄→安全点直线；
- `_path_risk()` 的敌方英雄项改用记忆风险；
- `_pick_safe_recall_turret()` 增加：
  - 塔被敌方小兵攻击则跳过；
  - 路径/点记忆风险惩罚；
  - 敌方小兵惩罚；
  - 无己方小兵掩护惩罚；
- 回城点缓存 0.8 秒内也要重新验证，不安全立即失效；
- 读条中改用 `_recall_point_threatened(hero.global_position)` 判断，敌兵/敌英雄记忆都能取消；
- 无安全塔/无草丛时 fallback 到己方泉水，避免原地不动。

## 二点二十七、赶路位移规则简化

按最新要求：

- 只要 `move_target` 距离 > 普攻距离，就尝试赶路位移/加速；
- 不再使用 `TRAVEL_DASH_MIN_DIST` 最短距离；
- 不再使用 `TRAVEL_DASH_ENEMY_GUARD` 附近敌人保护；
- 强化普攻赶路去掉马超/铠/不知火舞的额外距离门槛；
- 新增召唤师「疾跑」赶路：距离 > 普攻距离且可用即交；
- 保留施法/控制/回城/有 manual_target 时不赶路，以及终点不落敌塔。

## 二点二十八、赶路位移支持 manual_target 与加速技能

- 移除 `_try_travel_dash()` 的 `manual_target` 拦截：有目标时也允许用位移/加速赶路；
- 新增 `_pick_acceleration_skill()`：使用 `SkillDatabase.get_skill_fx()` 的 `selfspeed`/`msup` 标签识别加速技能；
- 赶路顺序：强化普攻位移 → 位移技能 → 加速技能 → 召唤师疾跑；
- 仍保留施法/控制/回城限制和落点安全。

## 二点二十九、统一路径入口

- 新增 `_sync_path_movement()`：所有非 manual_target 的 AI 移动目标都先经过 MovementPlanner，再以 waypoint 形式写给 Hero；
- Hero 自身只负责沿 waypoint 做局部 A*，不再由 AI 直接给最终点后各自寻路；
- manual_target 追击仍由 `_sync_ai_movement()` 走 MovementPlanner；
- SAFE_RECALL/RETURN_TO_BASE 使用 `_follow_safe_route()`，同样基于 MovementPlanner；
- 统一后 LaneStrategy/TaskExecutor 写出的 `move_target` 都会先被风险路径替换为 waypoint。

- 4 分钟后团队任务冒烟无脚本错误。
