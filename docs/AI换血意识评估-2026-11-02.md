# HonorKing AI 换血意识评估

评估时间：2026-11-02  
评估对象：当前单机 / 联机 host 的 AI 英雄  
评估标准：用户给出的「多人相遇 AI 攻防决策：换血意识」两层模型  
评估方法：代码审查 + 已有前 4 分钟固定阵容基准结果

---

## 一、结论

**当前 AI 不具备良好的换血意识。**

更准确的描述是：

> 它已经会“被打了就还手、残血就撤、有目标就放技能、追不上就用位移”，但还没有“先分析局势，再决定主动换血、换到什么程度、什么时候退出”的决策层。

| 维度 | 评分（10 分制） | 判断 |
|---|---:|---|
| 威胁指标计算 | 1.5 | 只有固定半径敌人数，没有血量×距离、视野记忆、动态范围 |
| 主动换血触发 | 3.0 | 只会被攻击后反击；没有技能就绪/强普/敌方被控的主动窗口 |
| 站位调整 | 2.0 | 只有低血回撤和弹道躲避；没有持续威胁规避/拉扯 |
| 多人目标与技能落点 | 2.5 | 有最低血/最近目标与 AoE 计数，没有目标优先级和站位优化 |
| 执行层 | 4.0 | 位移、连招、普攻原语齐全，但缺少“进场—换血—退出”编排 |
| **综合** | **2.8 / 10** | **不具备良好的换血意识** |

---

## 二、逐条对照用户定义

### 1. 分析层：判断能否主动换血

#### 1.1 威胁指标计算

用户要求：

- 15–20 米内英雄血量 × 距离系数，敌我差值；
- 小地图漏视野、不在附近敌人系数为 0；
- 视野消失敌人保留消失前血量和位置，并按时间衰减；
- 搜索距离随游戏时间动态增加。

当前实现：

- `AiPerception` 只用 `count_enemy_heroes_near(radius)` 统计**数量**；
- 半径是固定常量：`SIGHT_HERO=15`、`ENGAGE_RANGE=8`；
- 没有 `HP × 距离系数`，也没有敌我威胁总值；
- 敌人一旦进入草丛/隐身，`is_untargetable_by_enemies()` 直接跳过，**没有 last seen 位置/血量/时间记忆**；
- 没有随游戏时长扩大搜索半径；
- `LaneStrategy._is_defensive()` 只比较 12 米内可见双方英雄血量总和，不是威胁模型。

结论：**未实现。**

#### 1.2 主动换血触发场景

用户要求：

- 血量偏少但不危险、技能冷却好/有强普/敌方被控时，小幅前压放技能；
- 我方明显血量优势时主动换血；
- 其余情况持续调整站位，威胁低于阈值才停。

当前实现：

- `LaneStrategy._find_target()` 的优先级是：
  1. 最近攻击自己的英雄；
  2. 敌方小兵；
  3. 敌方英雄；
  4. 塔/野怪。
- 也就是说：**除非敌方英雄先攻击 AI，否则 AI 默认优先补兵**，不会根据技能/强普/控制主动找换血窗口；
- `HeroAI` 没有“强普已就绪”“敌方被控”“技能全好”这些换血前置条件；
- `SkillTactics` 只在已有 `manual_target` 且距离小于 10 米时尝试技能，不是主动换血决策；
- `HeroAI._try_upgrade_skills()` 不参与换血判断；
- 没有“小幅前压打一套再退”的状态。

结论：**只有“被打后反击”勉强算部分实现，主动换血未实现。**

#### 1.3 持续调整站位

用户要求：

- 计算移动方向降低自身威胁指标；
- 威胁低于阈值后停止调整。

当前实现：

- `HeroAI._retreat_behavior()` 只在血量低于 40% 且有敌人靠近时，向最近己方塔移动；
- `AiPerception.find_threatening_projectiles()` + `_dodge_threats()` 只躲避飞行物，不做威胁地形/站位；
- `Hero._physics_process` 的普攻自动追击会把 AI 拉向目标，可能主动走进更高威胁；
- 没有威胁梯度、没有侧移/拉扯/卡射程。

结论：**未实现。**

#### 1.4 多人换血：目标优先级与技能落点

用户要求：

- 多人目标优先级选择；
- 技能释放位置优化，先调站位再放，尽量命中更多敌人。

当前实现：

- `LaneStrategy` / `JungleStrategy` 的目标选择基本是“最低血量/最近/最后攻击者”；
- `SkillTactics._score_skill()` 对 AoE 技能按范围内敌人数加分；
- 但 `_aim_pos(target)` 只取**单个目标当前位置**，不会围绕目标簇寻找最优落点；
- 没有“先走位再放技能”的预施法位置评分；
- 没有按职责区分目标（切后排/保排/打前排）。

结论：**只有局部实现，达不到用户定义。**

---

### 2. 执行层：主动换血的执行

用户要求：

- 位移/加速/位移型强普拉近；
- 优先技能、连招；
- 持续普攻输出。

当前实现（这是相对最好的部分）：

- `_try_chase_dash()`：追击时用位移贴脸；
- `_try_escape_dash()`：低血被贴时位移拉开；
- `_try_travel_dash()`：非战斗赶路位移；
- `SkillTactics.try_best_combo()` + 通用/英雄 Brain：技能评分和连招链；
- 普攻由 Hero 自动执行，AI 设置 `manual_target` 即可持续输出；
- 召唤师/装备主动也接入了战术层。

但缺少：

- 没有“换血开始/结束”的统一状态；
- 没有“打一套后立刻后撤/等 CD”的退出条件；
- 没有按“敌方控制/我方技能 CD/双方血量”决定进场；
- 没有“射手打两下普攻就退”这类节奏；
- 没有多人战中的“先打谁、站在哪、何时撤”。

结论：**执行原语齐全，执行编排不足。**

## 三、当前 AI 在多人相遇时的实际行为

可以用一句话概括：

> 敌方先打我，我就打回去；有兵先补兵；血少就跑；技能好了就放；追不上就位移追；追不到就继续追。

这套行为的优点：

- 不会完全站桩；
- 被攻击会还手；
- 残血会回城/找塔；
- 技能、连招、追击和逃生原语都能用；
- 1v1 残局会收人头。

缺点：

- 不会主动制造换血窗口；
- 不会在换血前计算“我打他多少、他打我多少”；
- 不会在换血后主动脱离；
- 不会根据敌方消失前的信息做威胁估计；
- 不会为了多命中几个敌人而先走位；
- 容易被“打一下勾引—后撤—反打”这种真人操作骗。

## 四、已有测试结果对判断的支持

前一轮对“主动压英雄/补最后一下/塔下撤退”做过固定阵容基准：

- 主动压英雄版本：对英雄伤害 +18%，但死亡 +10%，CS 下降，塔伤下降约 67%；
- 补刀评分版本：CS 反而下降，塔伤下降；
- 最终均未达到验收门槛，已回滚。

这说明：

> **当前 AI 缺的不是“更敢打”，而是“先分析再打、打完知道退”。**  
> 单纯提高进攻权重只会让它更频繁地无意义换血，经济和塔伤反而变差。

## 五、建议的实现结构

### 1. `ThreatModel`（新增）

每帧/每 think 维护：

```
enemy_id
last_seen_pos
last_seen_hp
last_seen_time
visible
alive
```

计算：

- 动态视野半径：`15 + game_time/60 * 1.5`（示例）；
- 距离系数：`max(0, 1 - dist/radius)`；
- 时间系数：`exp(-(now-last_seen_time)/X)`；
- 英雄威胁值：`hp_ratio * distance_factor * time_factor`；
- 敌我威胁差 = 敌方威胁和 - 我方威胁和。

### 2. `TradePlanner`（新增）

每次决策输出：

```
TradeIntent:
  enter / hold / disengage
  target
  expected_damage_out
  expected_damage_in
  exit_hp
  exit_position
```

触发条件示例：

- 敌我威胁差有利；
- 关键技能 CD≤0；
- 有强普层数；
- 敌方被控/交完位移；
- 我在己方兵线/塔附近。

退出条件：

- 换血目标已达成（敌方掉血 > 我掉血 × 1.2）；
- 敌援军进入半径；
- 自身关键技能进入 CD；
- 血量低于安全线；
- 目标进入塔下/脱离射程。

### 3. `Positioning`（新增）

- 威胁梯度向量：向低威胁方向侧移；
- 射手保持最大射程边缘；
- 坦克/战士挡在队友与敌方之间；
- 法师在技能射程边缘，不被普攻范围覆盖。

### 4. 多人技能落点

- 对 AoE 技能枚举 5–9 个候选落点；
- 预测每个落点覆盖的敌人数、是否包含高价值目标、是否覆盖队友；
- 只有“多命中收益 > 走位风险”才先走位再放。

### 5. 执行层改造

把现有 `_try_chase_dash/_try_escape_dash/连招/普攻` 纳入 `TradePlan`：

- 进场：位移/加速/强普；
- 换血：技能→普攻；
- 退出：后撤/闪现/等 CD；
- 不允许“技能放完继续追到塔下”。

## 六、换血意识的评价指标

建议在 240 秒快照之外单独记录“换血事件”：

| 指标 | 定义 | 目标 |
|---|---|---|
| 主动换血次数 | AI 主动发起、非被攻击触发的交战 | 有，但不宜过多 |
| 换血胜率 | 换血结束时我方血量比例 > 敌方 | > 55% |
| HP 交换比 | 对英雄伤害 / 受到英雄伤害 | > 1.15 |
| 换血后死亡率 | 换血结束后 3 秒内死亡占比 | < 10% |
| 换血后 CS 损失 | 换血前后 10 秒补刀差 | < 10% |
| 无效换血率 | 换血后双方血量差接近 0 且丢失兵线 | < 20% |
| 技能命中率 | 换血窗口内技能命中/释放 | > 60% |
| 多目标命中率 | AoE 技能平均命中英雄数 | 越高越好 |
| 威胁降低率 | 站位调整后威胁值下降比例 | > 30% |
| 被消失视野敌人击杀率 | 被视野外/草丛敌人击杀占比 | 越低越好 |

当前已有的 `[AI-EARLY-METRICS]` 只覆盖阶段总账，**还不足以评价换血质量**；需要新增换血事件埋点。

## 七、结论与优先级

### 现状判断

**不具备良好的换血意识，约 2.8/10。**  
它是一个“有战斗原语的规则机器人”，还不是“会计算交换、会选择退出”的 AI。

### 建议优先级

1. **P0：威胁模型 + 视野记忆**（没有这个，后面都是拍脑袋）
2. **P0：换血进场/退出条件**（先解决“打一套就退”）
3. **P1：目标优先级与多人 AoE 落点**
4. **P1：站位/拉扯（射手走 A、坦克挡位、法师边缘输出）**
5. **P2：把换血行为接入英雄 Brain，按英雄机制差异化**

在完成 1、2 之前，不建议继续单纯提高“进攻性/压人”权重；已有基准已经证明那会让经济与塔伤变差。
