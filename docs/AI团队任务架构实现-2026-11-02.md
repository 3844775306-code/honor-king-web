# AI 团队任务架构实现记录

实现时间：2026-11-02  
目标：把原来的“只下发 lane 编号”升级为“团队任务 → 英雄执行器”。

---

## 一、实现内容

### 1. `TeamTask`：结构化主线任务

文件：[ai/TeamTask.gd](../ai/TeamTask.gd)

任务类型：

- PUSH_LANE：推线
- DEFEND_LANE：守塔/守高地
- OBJECTIVE：争夺龙/资源
- GANK：抓人/切后
- PEEL：保护射手/保排
- RETREAT：撤退

任务字段：

- 目标位置 / 目标英雄
- lane
- priority
- created_at / expires_at
- reason
- role_hint

### 2. `TeamTactics`：团队指挥官

文件：[ai/TeamTactics.gd](../ai/TeamTactics.gd)

- 重规划周期从 60 秒改为 **10 秒**；
- 增加 `request_replan()` / `consume_replan_request()`，塔数变化、龙存活变化时立即重规划；
- 每次分配生成 `tasks: {Hero: TeamTask}`；
- 根据局势生成：
  - 防守任务（压力最大分路）；
  - 资源任务（龙坑）；
  - 辅助 PEEL 射手；
  - 刺客 GANK；
  - 普通英雄 PUSH；
- 收集英雄 `task_feedback`，多人 `need_help` 时触发防守；
- 开局 `create_initial_tasks()`：0–4 分钟先下发一次基础任务，打野在龙未刷新时继续刷野而不是去空龙坑。

### 3. `TaskExecutor`：英雄执行器

文件：[ai/TaskExecutor.gd](../ai/TaskExecutor.gd)

- PUSH：同步任务跑道，继续走原 LaneStrategy；
- DEFEND：去目标塔，附近敌人可反击；
- OBJECTIVE：向龙坑集合，够得到就锁定资源；
- GANK：向目标英雄/区域移动；
- PEEL：跟射手，优先打射手附近的敌人；
- RETREAT：向安全点退。

### 4. HeroAI 接入

文件：[ai/HeroAI.gd](../ai/HeroAI.gd)

- 接收 `team_task`；
- 任务过期自动清理；
- 在生存/回城/守塔与换血之后执行任务；
- 推线任务继续交给 LaneStrategy；
- 其他任务由 TaskExecutor 给出明确 movement/target。

### 5. 反馈

`HeroAI.task_feedback()` 返回：

- 当前任务
- 血量比例
- 威胁值
- 是否需要支援
- 是否能接团

`TeamTactics` 在下一次分配时读取，不再完全依赖全知数据。

## 三、任务状态埋点

已加入 `TeamTask.Status`：

- ACTIVE
- COMPLETED
- FAILED
- EXPIRED
- REASSIGNED

`TeamTactics.update_tasks()` 每秒评估：

- 推线：目标敌方塔是否已不存在；
- 守塔：目标点周围是否连续 2.5 秒无敌人；
- 资源：目标区域是否还有野怪；
- 抓人：目标英雄是否已死亡/失效；
- 保排：射手周围是否连续 2.5 秒无敌人；
- owner 死亡 → FAILED，超时 → EXPIRED，重规划 → REASSIGNED。

`[AI-EARLY-METRICS]` 新增根字段：

```json
"task_stats": {
  "issued": 20,
  "completed": 1,
  "failed": 0,
  "expired": 9,
  "reassigned": 0
}
```

2 个种子的冒烟结果：

- 每局任务下发约 18–20 次；
- 4 分钟前大部分开局任务已过期/完成；
- 失败为 0，说明 DEFEND/PEEL 安全限制避免了任务执行期送死；
- 完成任务数仍偏少，后续需要提高 PUSH/GANK 任务的可完成率。

## 四、当前限制

- 任务层在 4 分钟后才进入完整周期重规划；0–4 分钟只下发一次初始任务；
- 任务完成判定还是启发式，PUSH/GANK 的完成率偏低；
- 任务类型已有，但职业差异和多人 AoE 落点还需要继续细化；
- 10 倍速/8 倍速 headless 结果只用于方向性比较。

---

## 五、下一步
