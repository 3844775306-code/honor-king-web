# HonorKing AI 英雄层架构文档

版本时间：2026-11-02  
对应代码：`ai/HeroAI.gd` 及 `ai/` 下各模块  
定位：团队任务层与 Hero 执行层之间的单英雄决策/行为层。

---

## 一、整体位置

```text
BattleManager
  └─ TeamTactics           团队任务层
       └─ TeamTask         团队任务数据
            └─ HeroAI      英雄层（本文档）
                 ├─ 感知 / 威胁 / 换血
                 ├─ 团队任务执行
                 ├─ 对线 / 打野本地策略
                 ├─ 技能 / 召唤师 / 装备主动
                 ├─ HeroBrain 英雄特判
                 └─ Hero    最终移动/普攻/施法执行
```

HeroAI 不直接移动角色，也不直接结算伤害。它只写：

- `hero.manual_target`
- `hero.move_target`
- `hero._start_casting(...)`
- `state`（行为标签，供战术层判断）

Hero 负责：

- 自动追击 `manual_target`
- `_avoid_walls()` 的 A* 移动
- 普攻、弹道、技能前摇/释放
- 位移技能的实际落点执行

## 三、HeroAI 生命周期

### 1. 初始化 `_ready()`

```text
找到父节点 Hero
→ AiPerception
→ ThreatModel
→ TradePlanner
→ TaskExecutor
→ SkillTactics / SummonerTactics / ItemActiveTactics
→ HeroBrain.create(display_name)
→ _assign_lane()
```

`_assign_lane()` 按职业确定 lane：

| 职业 | 默认 lane |
|---|---|
| 射手 | FARM |
| 法师 | MID |
| 刺客 | JUNGLE |
| 战士/坦克 | CLASH |
| 辅助 | FARM |

### 2. 每帧 `_process(delta)`

HeroAI 每帧运行，但真正“思考”按 think 间隔执行。

当前帧顺序如下。

```text
1. 被塔攻击检测 → _retreat_from_turret()
2. 弹道躲避 → _dodge_threats()，命中则 state=AVOID 并 return
3. manual_target 在敌塔下 → 清空目标
4. 死亡检查
5. ThreatModel.update()
6. TradePlanner.update()
7. 临时清兵计时暂停：_temp_clearing 时延长 team_task.expires_at
8. SkillTactics.update_combo()
9. 残血追击 _update_finish_chase()，命中则 return
10. 复活/泉水检测
11. think_timer 倒计时
12. think 到点：
    ├─ _try_teleport()
    ├─ brain.process_skill_windows()
    ├─ summoner_tactics.try_use(state, lane)
    ├─ item_tactics.try_use(state)
    ├─ brain.process_special_actions(state)
    ├─ _decide()
    ├─ _try_upgrade_skills()
    ├─ _ai_update_enhanced_attack_flag()
    ├─ _try_travel_dash()
    └─ 敌方 AI 可见性刷新
13. 购买
14. 恢复技能
15. 血包
16. 马超拾枪
17. RETREAT / RECALL_SAFE 状态行为，然后 return
18. 视野之灵
19. manual_target 技能/追击位移
```

### 3. 决策时钟

| 类型 | 间隔 |
|---|---:|
| 线上英雄 | `LANE_THINK_INTERVAL = 1.0s` |
| 打野 | `JUNGLE_THINK_INTERVAL = 0.5s` |

`_decide()` 只在 think 到点时执行。

## 四、英雄层实际执行优先级

### 1. 帧级抢占

这些逻辑在 `_decide()` 之前，优先级最高：

```text
被塔攻击逃生
→ 弹道躲避
→ 残血追击
→ 决策时钟
```

### 2. `_decide()` 内部顺序

当前实际顺序：

```text
1. 本线塔防御
2. 大禹治疗鼎
3. 泉水养伤
4. 低血回城（<25%）
5. 低血撤退（<40% 且 6m 内有敌人且不在己方塔下）
6. TradePlanner 换血（enter/hold/exit）
7. 临时清兵
8. TeamTask
9. 4 分钟前：LaneStrategy / JungleStrategy
10. 4 分钟后：打龙集合 / LaneStrategy / JungleStrategy
```

注意：

- 高地/水晶防御已经从英雄层移除，改由团队层守塔任务处理；
- 团队任务的 `priority` 只用于任务之间的抢占，不能压过上面的生存/换血/临时清兵；
- 任务 priority 在 `assign_team_task()` 中比较：高优先级抢占、低优先级保留、同优先级 2 秒承诺窗口。

### 3. 状态 vs 决策

`state` 只是行为标签：

```gdscript
enum State { PUSH, FARM, RETREAT, RECALL, AVOID, RECALL_SAFE }
```

- `RECALL` 当前基本不用；
- `RETREAT` / `RECALL_SAFE` 会让 `_process()` 跳过输出；
- 真正分支都在 `_process` / `_decide` 的 if 里，不在 enum 上。

## 五、目标来源

`hero.manual_target` / `hero.move_target` 可能来自：

| 来源 | 写入者 | 说明 |
|---|---|---|
| 团队任务 | TaskExecutor | PUSH_TOWER/PUSH_LANE 主要给 lane，其他任务给目标 |
| 换血 | TradePlanner | `enter/hold` 锁目标，`exit` 给撤退点 |
| 对线 | LaneStrategy | 0–4 分钟或本地兜底 |
| 打野 | JungleStrategy | 自然打野 |
| 打龙 | `_dragon_rally_behavior()` | 龙/暴君 |
| 残血追击 | `_update_finish_chase()` | 单独目标 `_chase_target` |
| 临时清兵 | `_try_temp_clear()` | 敌方小兵 |
| 塔防御 | `_handle_lane_turret_defense()` | 本线塔 |
| 撤退 | `_retreat_behavior()` | 安全路线 |
| 回城 | `_recall_safe_behavior()` | 回城点 |

## 六、TeamTask 执行

### 1. 接任务

`assign_team_task(task)`：

- 当前没有任务 / 当前任务失效 → 接受；
- 新任务 priority < 当前 priority → 拒绝；
- 新任务 priority > 当前 priority → 抢占；
- 同 priority → 2 秒承诺窗口，窗口内不换。

### 2. 执行

`TaskExecutor.execute(task, now)` 输出：

```text
{
  "lane": int,               # 可选，交给 LaneStrategy
  "manual_target": Node,     # 可选
  "move_target": Vector3,    # 可选
  "state": "push"/"retreat"
}
```

当前任务行为：

| 任务 | 执行方式 |
|---|---|
| PUSH_LANE | 交给 LaneStrategy，仅同步 lane |
| PUSH_TOWER | 交给 LaneStrategy，仅同步 lane |
| DEFEND_LANE | 到水晶附近清敌方小兵 |
| OBJECTIVE | 去龙坑，够得到就打野怪 |
| GANK | 锁落单英雄/去目标点 |
| PEEL | 跟射手，攻击射手附近敌人 |
| INVADE_JUNGLE | 去敌方野区最近营地 |
| RETREAT | 仅枚举，TeamTactics 不生成 |

### 3. 临时清兵

插入在 **TradePlanner 之后、TeamTask 之前**：

- 动态范围：`15 + clamp((actual_move_speed - 6) / 2, 0, 5)`，最多 20m；
- 选择安全的敌方小兵；
- 路径整条不能进入敌方塔射程；
- 执行期间暂停 `team_task.expires_at`；
- 周围没有敌方小兵后自动结束。

## 七、对线与打野本地策略

### LaneStrategy

- 0–4 分钟主要使用；
- 4 分钟后作为本地兜底；
- 负责补刀、推兵、塔下安全、回撤。

### JungleStrategy

- 自然打野使用；
- 负责野区路线、gank、回线；
- 0–4 分钟按阶段推进，4 分钟后继续本地兜底。

当前结构是：

```text
TeamTask（如果有）
→ 若任务交给 LaneStrategy，则 LaneStrategy 继续决策
→ 否则 TeamTask 直接给目标
```

也就是说，本地策略和团队任务还没有完全统一成单一行为层。

## 八、换血层

`TradePlanner` 负责：

- 目标评分；
- 进场条件；
- 2.4 秒换血窗口；
- 38% 血量退出；
- 2.8 秒冷却；
- 输出换血统计。

它在 `_decide()` 中位于：

```text
低血撤退
→ TradePlanner
→ 临时清兵
→ TeamTask
```

所以：

- 换血可以压过团队任务；
- 但低于低血回城/撤退。

### ThreatModel

- 记录敌人最后位置、血量、时间；
- 计算 `血量 × 距离 × 时间衰减`；
- 为 TradePlanner/撤退/安全点提供威胁值。

## 十、移动与位移

### 普通移动

- HeroAI 写 `move_target`；
- Hero 使用 `_avoid_walls()`；
- `_avoid_walls()` 内部用 A* 路径，带卡墙恢复；
- 追击 `manual_target` 时由 Hero 自带 AI 自动靠近。

### 位移

| 类型 | 入口 | 条件 |
|---|---|---|
| 追击位移 | `_try_chase_dash()` | 目标不在普攻距离、距离≤14m、位移后够得到、落点安全 |
| 逃跑位移 | `_try_escape_dash()` | RETREAT 状态、血量≤55%、8m 内有敌人 |
| 赶路位移 | `_try_travel_dash()` | PUSH/FARM、无 manual_target、距离>9m、15m 无敌人 |
| 闪现赶路 | `_try_flash_travel()` | 直线被墙挡、绕路>1.6 倍 |
| 战斗闪现 | `SummonerTactics._try_flash()` | 低血危险逃跑 / 进攻闪现 |

### 落点安全

`_resolve_dash_end()`：

- 落点可站立；
- 落点不能太远；
- 被墙挡时，只有绕路 >1.6 倍才允许穿墙；
- 落点不能在敌方塔射程内。

### 历史/当前风险

- 被塔攻击逃生 `_retreat_from_turret()` 仍是直线，不走 A*；
- 战斗闪现只校验可站立，不校验敌方塔落点；
- `_try_escape_dash()` 不处理 RECALL_SAFE 状态；
- 追击技能只按 `SKILL_USE_RANGE` 判断，不区分远程/控制/近战；
- 位移落点不检查敌方英雄；
- 团队任务无法直接指挥“交闪现/交位移”。

## 十二、当前架构的主要问题

1. **优先级分散**
   - 帧级抢占、`_decide()`、任务 priority、TradePlanner、LaneStrategy 各有一套顺序；
   - 没有统一的 ActionScheduler。

2. **团队任务与本地策略仍未完全合并**
   - PUSH_LANE 仍交给 LaneStrategy；
   - TeamTask 和 LaneStrategy 都可能改目标。

3. **状态机是标签，不是真正状态机**
   - `State` 只是字符串语义；
   - 各分支散落在 `_process` / `_decide`。

4. **临时清兵可能过度抢占**
   - 它可以压过团队任务和推塔；
   - 虽然已避开敌塔路线，但仍可能让 AI 长时间不推塔。

5. **撤退/闪现安全不完整**
   - 塔攻击逃生仍直线；
   - 战斗闪现不检查敌塔。

6. **感知偏全知**
   - 很多逻辑直接遍历全场节点；
   - 没有统一的“可见/记忆/预测”边界。

## 十三、建议的调整切入点

如果后续要重构英雄层，建议优先改这四块：

### A. 唯一决策入口

把所有行为统一成：

```text
Behavior.evaluate() → Action
ActionScheduler.pick() → 执行
```

Action 至少包含：

```text
type: move / attack / cast / dash / flash / recall / retreat
priority
target
position
expires_at
reason
```

### B. 统一优先级

建议：

```text
生存/回城
→ 帧级躲避/塔逃生
→ 临时清兵
→ 换血
→ 团队任务
→ 本地对线/打野
→ 赶路位移
```

### C. 移动与位移统一

- 普通移动、撤退、回城统一走 A*；
- 位移作为特殊 edge，显式检查：
  - 落点可站立；
  - 不穿敌塔；
  - 不落敌群；
  - 是否有逃生价值。

### D. 感知统一

- 可见目标；
- 最后视野；
- 记忆时间；
- 预测位置；
- 避免 `LaneStrategy` / `TradePlanner` / `ThreatModel` 各自扫全场。

---

## 十四、如果要继续调整

可以从以下任一层开始：

1. 只改 `_decide()` 优先级；
2. 只改 TeamTask / TaskExecutor 接口；
3. 只改 LaneStrategy / JungleStrategy 的交接方式；
4. 把 HeroAI 拆成 `ActionScheduler + Behaviors`；
5. 统一感知与移动。
