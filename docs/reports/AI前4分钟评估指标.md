# HonorKing AI 前 4 分钟评估指标

更新时间：2026-11-01  
范围：0:00–4:00，单机 / 联机 host 的 AI 英雄  
目的：把“完整对局 AI”拆成可迭代的小阶段，先用数据判断前 4 分钟改动是否有效，再进入中期运营和团战阶段。

---

## 一、为什么先评估前 4 分钟

前 4 分钟决定后续几乎所有节奏：

- 对线补刀、等级、血量、召唤师技能状态；
- 打野第一轮路线和 gank 成功率；
- 一血、第一条龙前的视野/站位；
- 防御塔血量和兵线位置。

这段的 KPI 比“整局胜率”更敏感，改动能在一局很短时间内被观察到，适合做第一阶段迭代。

---

## 二、核心指标（Primary KPI）

| 指标 | 公式 / 口径 | 观察对象 | 目标方向 |
|---|---|---|---|
| CS/分钟 | `last_hits / 4` | 对线英雄 | +10% 以上 |
| 金币/分钟 | `total_gold_earned / 4` | 全 AI | +8% 以上 |
| 等级差 | AI 等级 - 对位敌人等级 | 对线英雄 | 不低于 -0.5 |
| 死亡数/4分钟 | `deaths` | 全 AI | -15% 以上 |
| 早期崩盘率 | 4 分钟前死亡 ≥3 的 AI 占比 | 全 AI | -20% 以上 |
| 伤害/死亡 | `damage_dealt_to_heroes / max(deaths,1)` | 全 AI | +10% 以上 |
| 击杀参与率 | `(kills + assists) / 团队击杀` | 全 AI | +5% 以上 |
| 塔伤/4分钟 | `turret_damage` | 战士/射手/法师 | 不降低 |
| 打野金币/分钟 | `jungle_gold / 4` | 刺客/打野 | +10% 以上 |
| 无效越塔死亡 | 塔下死亡数 / 总死亡数 | 全 AI | 越低越好，目标 -30% |
| 早期推塔数 | 4 分钟时敌方存活外塔数 | 团队 | 不劣于改动前 |

> 不建议只看“4 分钟击杀数”：击杀可能来自对面送，也可能牺牲补刀和塔伤。必须和 CS、金币、塔伤一起看。

---

## 三、二级指标（诊断用）

| 指标 | 说明 | 用途 |
|---|---|---|
| 对位补刀差 | 同路 AI 与敌方 AI 的 `last_hits` 差 | 判断线权/补刀能力 |
| 对位血量差 | 4 分钟时同路双方血量比例差 | 判断换血是否吃亏 |
| 回城次数/有效回城率 | 回城后是否带着足够装备/状态回线 | 判断资源利用 |
| 首次死亡时间 | 第一次死亡发生的游戏时间 | 判断前期稳定性 |
| 打野首轮清野时间 | 第一轮野区清空时间 | 判断路线效率 |
| gank 成功率 | gank 后击杀/助攻或逼出闪现的比例 | 判断打野质量 |
| 塔下停留时间 | AI 在敌方塔攻击范围内累计时间 | 判断越塔风险 |
| 无效游走率 | 没有目标/没有收益的转线次数 | 判断宏观决策 |
| 超时决策率 | 决策被跳过或长时间无目标的比例 | 判断难度/性能 |
| AI 思考耗时 | 单次 think tick 的耗时 | 性能回归 |

这些指标中，`last_hits`、金币、死亡、塔伤、伤害已经可以直接从 Hero 统计字段采集；`塔下停留`、`无效游走`、`gank 成功率` 需要后续加埋点。

## 四、当前自动采集

### 触发时机

游戏时间到达 **240 秒** 时，`BattleManager` 自动输出一次前 4 分钟快照。

### 输出位置

1. 控制台：`[AI-EARLY-METRICS] {...JSON...}`
2. 文件：`user://ai_early_metrics.json`

### 字段

```json
{
  "t": 240.0,
  "player_towers": 3,
  "enemy_towers": 3,
  "totals": {
    "player": {"kills": 0, "deaths": 0, "cs": 0, "gold": 0},
    "enemy": {"kills": 0, "deaths": 0, "cs": 0, "gold": 0}
  },
  "heroes": [
    {
      "name": "亚瑟",
      "role": "战士",
      "team": 0,
      "is_ai": true,
      "lane": "对抗路",
      "level": 5,
      "kills": 0,
      "deaths": 0,
      "assists": 0,
      "cs": 24,
      "gold": 2300,
      "damage_heroes": 1200,
      "damage_taken": 1800,
      "turret_damage": 300,
      "jungle_gold": 0
    }
  ]
}
```

### 采集命令

```powershell
godot --headless --path . --quit-after 16000 res://scenes/battle.tscn -- --net-test
```

然后从日志中提取：

```powershell
Select-String -Path log.txt -Pattern '^\[AI-EARLY-METRICS\]'
```

> 当前 headless 测试中玩家英雄可能原地不动，适合看 AI 行为，不适合作为真人强度基准。

## 五、改动后建议的验收门槛

以当前版本为基线，完成前 4 分钟 AI 改动后，连续跑至少 10 局同阵容 AI 对局，满足以下条件才算有效：

- CS/分钟：+10% 以上；
- 金币/分钟：+8% 以上；
- 死亡数/4分钟：下降 15% 以上；
- 塔下死亡占比：下降 30% 以上；
- 打野金币/分钟：+10% 以上；
- 早期推塔数：不下降；
- 对位等级差：不明显恶化。

如果出现“击杀提高但 CS/塔伤下降”，说明 AI 变得更爱打架但没有转化成优势，需要回退目标评分权重。

## 六、分阶段路线

### 阶段 1：0–4 分钟（当前）

重点：

- 对线补刀与换血；
- 打野首轮路线与 gank 安全；
- 避免无意义越塔；
- 建立指标基线。

### 阶段 2：4–10 分钟

重点：

- 第一条龙/先锋决策；
- 分推与抱团；
- 辅助游走、保排。

### 阶段 3：10 分钟后

重点：

- 团战集火/开团/拉扯；
- 高地攻防；
- 资源交换与终结比赛。

---

## 七、当前局限

- 项目没有现成 AI 自动测试套件，当前快照是单次采样，不是统计置信区间。
- 还没有记录“塔下停留时间”“gank 成功率”“无效游走”，这些需要后续埋点。
- headless 对局中玩家英雄不会主动操作，不能直接代表真人局胜率。
- 评估结论必须结合录像回放和人工观战，不能只看 JSON。

---

## 八、结论

前 4 分钟的评估应围绕三件事：

1. **AI 能不能稳定发育**：CS、金币、等级、死亡；
2. **AI 的优势能不能转化**：伤害/死亡、塔伤、击杀参与；
3. **AI 会不会无意义送节奏**：塔下死亡、无效游走、早期崩盘率。

先用这套指标跑出基线，再调目标评分、打野安全和越塔判断，才能避免“感觉变强了、实际经济更差”的假优化。
