# AI 团队指挥官 / 英雄执行双层架构评估

评估时间：2026-11-02  
评估对象：当前单机 / 联机 host AI  
参考架构：团队指挥官（游戏时间 + 战场形势 + 职业分工 → 主线任务）  
　　　　　→ 英雄层（接收任务 → 默认走位/目标 + 周围威胁分析 → 实际走位/攻击）

---

## 一、先评价架构本身

### 结论

这个双层架构**方向正确，适合 MOBA**，比“每个英雄各自看全场”更容易做出：

- 分推、抱团、守家、打龙、抓单等团队行为；
- 职业分工与阵容职责；
- 统一的资源交换和节奏；
- 可解释、可调试的 AI（团队任务可以显示、记录、回放）。

但它能否落地，取决于两个关键契约：

1. **团队层输出的“主线任务”必须是一个结构化对象**，不能只是“去某条路”；
2. **英雄层必须有任务执行器 + 反馈**，不能只是“收到一个 lane 后继续自己找目标”。

如果这两点不做，最终会退化成：

> 团队层随机分路，英雄层按自己的局部规则乱打，两层互相覆盖。

### 架构优点

- **分层清晰**：全局节奏和局部操作分开，符合 MOBA 的决策粒度。
- **职业分工可表达**：坦克开团、辅助保排、刺客切后、射手发育都能落到任务上。
- **可扩展**：新增目标（暴君/主宰/高地/视野之灵）只需新增任务类型，不必改每个英雄。
- **可观测**：任务可以显示在 HUD/日志里，便于复盘。
- **保留英雄自主性**：英雄层仍可因生存/技能 CD/威胁临时偏离任务。

### 架构风险

1. **指挥官信息过载 / 全知**
   - 如果团队层直接读取所有敌人位置、所有塔血、所有经济，AI 会像开图。
   - 需要输入“带视野约束的战场快照”，而不是直接访问世界。

2. **任务接口不完整**
   - 只给“去哪”不够，还需要：
     - 任务类型（推线/守塔/打龙/抓人/保排/撤退/发育）；
     - 目标（塔/龙/英雄/区域）；
     - 优先级；
     - 创建时间与过期时间；
     - 中止条件；
     - 完成条件。

3. **没有反馈回路**
   - 英雄层需要向团队层反馈：
     - 任务进度；
     - 当前威胁；
     - 血量/蓝量/技能 CD；
     - 是否能接团；
     - 是否请求支援。
   - 没有反馈，指挥官无法动态改任务。

4. **重规划频率**
   - 60 秒一次太慢。MOBA 的关键事件是秒级的：塔被攻击、龙刷新、队友阵亡、敌方消失。
   - 团队层应“事件驱动 + 周期兜底”，而不是纯周期。

5. **任务与生存冲突**
   - 团队层说“推塔”，英雄层发现三人包夹，必须允许自动中止并回撤。
   - 需要明确的优先级：生存 > 防守高地 > 团队目标 > 推线 > 发育。

6. **职责定义不足**
   - “按职业分工”不能只看坦克/战士/刺客；
   - 辅助要跟射手/游走/保排，坦克要开团/挡位，射手要保持射程，法师要边缘输出。

## 二、当前 AI 的实现度

### 总体判断

当前 AI **有双层架构的骨架，但没有完整的任务链路**。

| 架构能力 | 实现度 | 说明 |
|---|---:|---|
| 团队层输入：游戏时间 | 80% | `TeamTactics` 读取 `game_time` |
| 团队层输入：战场形势 | 45% | 有经济、塔数、水晶威胁、龙存活；缺视野、兵线压力、敌方 CD/等级、资源即将刷新 |
| 团队层按职业分工 | 40% | 仅按坦克/战士/刺客粗分；辅助、射手、法师职责未形成任务 |
| 团队层输出主线任务 | 20% | 只输出 lane / 打龙标记，没有任务类型、目标、优先级、过期 |
| 英雄层接收任务 | 30% | `apply_team_lane` / `is_dragon_rally`，没有任务执行器 |
| 英雄层默认走位/目标 | 75% | `LaneStrategy`、`JungleStrategy` 能默认推线/刷野 |
| 英雄层威胁分析 | 50% | 新 `ThreatModel` + `TradePlanner` 已接入换血；但默认走位/对线仍未完全使用 |
| 英雄层最终走位/攻击 | 75% | `manual_target` / `move_target` / 技能连招可执行 |
| 团队-英雄反馈 | 10% | 没有任务进度、威胁、CD、接团意愿回传 |
| **综合** | **约 42%** | **骨架有，任务链未打通** |

## 三、逐层对照

### 1. 团队层：团队指挥官

当前实现文件：

- `ai/TeamTactics.gd`
- `scripts/core/BattleManager.gd` 中的 `team_tactics` 调用
- `_distribute_lane_assignments()`

已经有的：

- 4 分钟后每 60 秒执行一次 `allocate_all()`；
- 读取经济差、塔数、水晶是否被威胁、龙是否存活；
- 选择 `4-1 / 1-3-1 / 打龙 / 防守` 模式；
- 给每个 AI 一个 `lane` 或“打龙”标记；
- 简单按职业把坦克/战士分到相邻路，刺客在 1-3-1 中分到剩余路。

不足：

- 0–4 分钟没有团队层，只有每个英雄自己的 `_assign_lane`；
- 输出只有 `lane int`，不能表达：
  - “守上路二塔，不要接团”；
  - “推中路线，然后转龙”；
  - “辅助跟射手，不要单走”；
  - “等敌方交完技能再开团”；
- 没有任务优先级、过期时间、完成条件；
- 60 秒周期不能响应塔被攻击、队友阵亡、龙刷新等事件；
- 团队层和英雄层可能互相覆盖：
  - 团队层分配“打龙”；
  - 英雄层发现本线塔被攻击，转去防守；
  - 没有仲裁，任务状态也不回传。

### 2. 英雄层

当前实现文件：

- `ai/HeroAI.gd`
- `ai/LaneStrategy.gd`
- `ai/JungleStrategy.gd`
- `ai/ThreatModel.gd`
- `ai/TradePlanner.gd`
- `ai/tactics/*`

已经有的：

- 接收 lane 后由 `LaneStrategy` 生成默认目标/走位；
- 打野由 `JungleStrategy` 生成刷野/gank 目标；
- `ThreatModel` 已提供视野记忆、动态威胁值和安全点；
- `TradePlanner` 已能主动换血、控制换血窗口、退出；
- 技能、连招、普攻、位移执行层齐全。

不足：

- 没有“主线任务”对象，只有 lane 和打龙标记；
- `LaneStrategy` 默认走位仍是局部目标搜索，不是“执行团队任务”；
- `ThreatModel` 目前主要服务于换血，没有持续影响默认走位/站位；
- 没有任务进度上报；
- 没有“任务允许我打到什么程度”的边界；
- 多人目标优先级、AoE 落点还没有完全任务化。

## 四、当前 AI 实际运行链路

```text
BattleManager
  └─ 4min 后每 60s TeamTactics.allocate_all()
       └─ 输出 {Hero: lane} 或 JUNGLE(打龙)
            └─ HeroAI.apply_team_lane(lane)
                 ├─ pending_lane
                 └─ LaneStrategy / JungleStrategy 自己找目标

HeroAI 每帧
  ├─ 生存/回城/守塔
  ├─ ThreatModel + TradePlanner（主动换血）
  ├─ Lane/Jungle 局部目标
  └─ 技能/普攻/位移执行
```

这是“**团队分路 + 英雄局部策略 + 新换血层**”的组合，不是完整的“团队任务 → 英雄执行”。

## 五、修改建议

### P0：把“主线任务”定义成结构化对象

建议新增：

```gdscript
class TeamTask:
    var id: String
    var type: int          # PUSH / DEFEND / GANK / JUNGLE / OBJECTIVE / GROUP / PEEL / RETREAT / FARM
    var target: Vector3 / Node
    var priority: int      # 生存 > 高地 > 目标 > 推线 > 发育
    var created_at: float
    var expires_at: float
    var reason: String
    var role_hint: String
```

团队层输出的不再只是 `lane`，而是：

- `type`
- `target`
- `priority`
- `expires_at`
- `abort_conditions`
- `role_hint`

### P0：团队层改为事件驱动 + 低频兜底

触发点：

- 防御塔被攻击；
- 水晶/高地受威胁；
- 龙/主宰刷新或即将刷新；
- 队友阵亡；
- 敌方关键英雄消失；
- 经济差跨阈值；
- 10 秒周期兜底重规划。

不再固定 60 秒才反应。

### P1：英雄层增加 TaskExecutor

`HeroAI` 收到 `TeamTask` 后：

1. 将任务转为期望位置/目标；
2. 用 `ThreatModel` 计算路径威胁；
3. 用 `TradePlanner` 决定是否接战；
4. 按任务类型执行：
   - PUSH：带线推塔，不追人；
   - DEFEND：守塔/守高地，不越塔；
   - GANK：绕后/等控制；
   - OBJECTIVE：集合打龙/逼团；
   - PEEL：跟射手/打断突进；
   - RETREAT：向安全点退。

任务执行器需要：
- 完成任务上报；
- 受阻上报；
- 请求支援；
- 自动中止（生命危险/人数劣势）。

### P1：加入团队黑板上报

每 0.5–1 秒或事件触发，英雄层回传：

```text
position / hp / mana / level
current task / progress
threat level
key cooldowns
can_engage
need_help
```

团队指挥官根据报告重新分配任务，而不是每 60 秒盲判。

### P1：职业分工细化

- 坦克：开团/挡位/吃塔伤；
- 战士：侧翼/切后/分推；
- 刺客：绕后/抓单/资源争夺；
- 法师：边缘 AoE/守中；
- 射手：发育/持续输出/保持射程；
- 辅助：跟射手/游走/保排/让经济。

任务必须带 `role_hint`，英雄层再按自己的职责决定执行方式。

### P2：把威胁分析用于默认走位

当前 `ThreatModel` 只在换血时使用。建议：

- 在没有任务或任务为 PUSH/FARM 时，持续用 `safe_position()` / 威胁梯度微调站位；
- 让射手保持最大射程边缘，坦克站到队友与敌人之间；
- 任务执行路径经过高威胁区时绕行或等队友。

### P2：0–4 分钟也纳入团队层

当前前 4 分钟是每个英雄自己 `_assign_lane`。建议团队指挥官在开局就生成：

- 分路任务；
- 打野路线；
- 辅助跟射手；
- 第一波线权/河蟹/防守任务。

## 六、建议的验收指标

| 指标 | 目标 |
|---|---:|
| 任务完成率 | 上升 |
| 任务平均执行时长 / 无效切换次数 | 下降 |
| 团队目标转化率（塔/龙/高地） | 上升 |
| 任务期间死亡率 | 下降 |
| 团队集火率 | 上升 |
| 辅助参团/保排成功率 | 上升 |
| 任务与站位一致率 | 上升 |
| 任务超时率 | 下降 |
| 同经济下胜率/推塔数 | 上升 |

现有 `--ai-bench` 已能做固定阵容基准；下一步需要给任务系统加事件埋点，否则只能看总账。

---

## 七、最终判断

这个双层架构本身是**正确的**，比当前“团队分路 + 英雄局部规则”更接近真人 MOBA 的决策方式。

但当前实现度大约只有 **42%**：

- 团队层有分路/打龙/防守的雏形；
- 英雄层有默认走位、攻击和新的威胁/换血模块；
- 但**没有结构化主线任务、没有任务执行器、没有反馈回路、没有事件驱动重规划**。

所以现在不能称为“完整的团队指挥官 + 英雄执行链路”，只能称为“团队分路 + 英雄局部 AI + 新增换血分析”。

下一步优先级应该是：

1. `TeamTask` 结构化；
2. 事件驱动指挥官；
3. `TaskExecutor` + 反馈；
4. 职业任务化；
5. 威胁模型进入默认走位；
6. 0–4 分钟团队化。
