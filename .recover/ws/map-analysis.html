发现问题

1. 坐标编码错误 — 多处双负号
红方野区坐标使用了 --（双负号）语法，如 Vector3(--12, 0, -26)、Vector3(--58, 0, --58)。在 GDScript 中这会被解析为两次取反运算符，刚好得到正数，但这是巧合而非设计要求。应改为显式正数坐标。
2. 史诗野怪 Timer 初始化问题
tyrant_timer 和 dragon_timer 初始值为 0.0，意味着游戏开始时就会立即尝试生成。实际的 4 分钟延迟依赖 _update_epic_monsters 在 game_time >= 240 时才被调用。如果未来修改了时间判断逻辑，可能在 0 秒时错误生成。
3. 河道碰撞缺失
河道只有视觉平面，没有独立的碰撞体。地面碰撞统一由 120×120 的 StaticBody3D 提供，这意味着河道在碰撞检测上与普通地面无异 — 站在河道中没有减速或其他效果。
4. 高地圆盘非真实圆形
_create_circle_plane 创建的是方形 PlaneMesh（边长 = 半径×2），而非真正的圆盘。命名具有误导性 — 视觉上它是一个正方形的色块。
5. 野区活动范围环使用 TorusMesh 但不使用 MeshFactory
_spawn_jungle_group、_spawn_tyrant、_spawn_dragon 中的活动范围环（~15 行）仍使用原始 TorusMesh + StandardMaterial3D 创建，可改用 MeshFactory.create_torus_ring()。
6. 蓝方红 Buff 位置异常
蓝方红 Buff 位于 (0, 0, 40) — 在河道正上方，而非野区深处。这与其他野怪的位置模式不一致，可能是占位数据。
7. 沙蚕跨象限放置
蓝方沙蚕位于 (-45, 0, -25) — 这是红方半区（Z 为负），应为蓝方半区（Z 为正）的野怪。这是镜像逻辑不一致。
8. 墙体无碰撞尺寸变化
所有 30 面墙的位置都有硬编码坐标，但 Wall 实体使用的是默认碰撞体积。大量墙体之间没有形成连续的障碍物链，玩家可能从墙间缝隙穿过。
